# Безопасность PSrazmer PRO 2.7

## Модель данных
База SQLite локальная. Резервные копии создаются перед изменениями и один раз в день. Проверяется целостность созданной копии. Журнал действий хранится в той же базе, поэтому администратору следует регулярно копировать базу и резервные копии на защищённый носитель.

## Рекомендации Windows
1. Используйте отдельные учётные записи Windows для операторов.
2. Установите NTFS-права на каталоги данных так, чтобы фото, база и резервные копии не были доступны всем пользователям ПК.
3. Включите BitLocker или другое штатное шифрование диска.
4. Не запускайте программу с правами администратора без необходимости.
5. Не храните резервные копии в синхронизируемой общедоступной папке.
6. Проверяйте восстановление резервной копии на отдельном тестовом экземпляре.

## Следующий этап для нескольких рабочих мест
Для нескольких операторов следует перейти на серверную БД с индивидуальной аутентификацией, ролями (оператор/руководитель/администратор), TLS, журналом на сервере, резервированием и блокировкой номеров на серверной стороне. Не следует одновременно открывать одну SQLite-базу через сетевой диск как замену серверу.

## Интеграция Magicard
Пока используется безопасный файловый обмен: создаётся копия `.card`, оригинал не изменяется. У Magicard есть отдельный Magicard SDK для приложений печати и управления принтером (официальная точка получения: https://techs.magicard.com/sdk). Это не означает, что сам HUB предоставляет публичный API. Перед интеграцией необходимо получить SDK и руководство, проверить лицензию и совместимость с Magicard 300/драйвером, затем реализовать адаптер с обработкой ошибок и подтверждением статуса задания. В этой версии SDK не подключён.

## Интеграционный контур 2.8.5
Перед выпуском откройте вкладку «Magicard HUB» и нажмите «Проверить шаблон». Программа проверит JSON-структуру, фотообъект `images.jpg` и оба встроенных изображения. При выпуске создаётся отдельная копия `.card`; исходный шаблон не должен перезаписываться. Запись проходит через временный файл и проверяется до атомарной замены конечного файла.

Программа не внедряется в закрытые внутренние интерфейсы HUB и не управляет печатью напрямую. Это сделано намеренно: автоматизация неподтверждённых внутренних API может повредить дизайн или привести к неверной печати. После создания `.card` откройте его в Magicard HUB, визуально проверьте лицевую/оборотную стороны, затем печатайте штатными средствами HUB.


## Интеграция 2.9.0
- Путь к HUB определяется автоматически только по зарегистрированным App Paths и нескольким стандартным каталогам; пользователь может указать путь вручную.
- Готовый `.card` открывается через ассоциацию Windows с расширением `.card`. Если ассоциация не настроена, программа предлагает ручное открытие; запуск HUB с аргументом файла используется только как резервная попытка и зависит от поддержки этой команды конкретной версией HUB.
- Встроенный preview извлекается только для визуальной проверки. Он не доказывает физический размер, точность цветов или готовность печати.
- Проверка сравнивает копию с исходным шаблоном и допускает изменение только `base64image`, `originalBase64Image` у единственного `images.jpg` и `about.preview`.
- В пакетном режиме существующие файлы не перезаписываются.
- Восстановление БД сначала проверяет SQLite integrity и наличие таблицы сотрудников, сохраняет текущую БД и только затем заменяет её проверенной копией.
- Прямое управление принтером, запуск печати и закрытые внутренние API HUB не используются.


## Как работает открытие карточки
1. На Windows программа сначала передаёт `.card` системной ассоциации файла. Если расширение связано с Magicard HUB, карточка откроется в нём.
2. Если ассоциация отсутствует, укажите `MagicardHUB.exe` вручную в настройках и назначьте `.card` приложению Magicard HUB в параметрах Windows.
3. Команда запуска EXE с путём к `.card` является резервной попыткой: конкретная версия HUB может не поддерживать такой аргумент. В этом случае откройте файл через меню HUB.
