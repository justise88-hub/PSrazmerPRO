# PSrazmer PRO 2.7 — Magicard HUB 2.0.6 / Magicard 300

Разработчик: **P.Sveshnikov**

## Что изменено относительно 2.6

- Исправлена ошибка в подготовке фото сотрудника: удалено обращение к неинициализированному объекту шаблона.
- Добавлена таблица `audit_log` и отображение последних действий в разделе «История и резервные копии».
- Добавлена запись событий создания, изменения и удаления карточки сотрудника.
- Подготовка индивидуального `.card` фиксируется как `hub_card_prepared`; это не является подтверждением физической печати.
- Выдача номера при добавлении сотрудника выполняется под SQLite `BEGIN IMMEDIATE`: следующий номер пересчитывается под блокировкой, повторно проверяется уникальность.
- Добавлен частичный уникальный индекс для непустых номеров (если в старой базе нет дубликатов). Для старой базы с дубликатами приложение сохраняет прикладную проверку и пишет сообщение в лог.
- Редактирование номера также проверяется внутри транзакции.
- `.card` сначала записывается во временный файл и проверяется как JSON, затем атомарно заменяет целевой файл.
- Для SQLite задан таймаут ожидания блокировки 30 секунд.
- Резервная копия проверяется `PRAGMA integrity_check`; при запуске создаётся не более одной автоматической копии в день. Сохраняются последние 30 файлов резервных копий.
- Исходный шаблон и исходные фотографии не изменяются.

## Запуск

1. Распакуйте архив в папку, доступную для записи текущему пользователю.
2. Установите Python 3.10+ (если запускаете из исходников).
3. Выполните `run_windows.bat` или установите зависимости командой `pip install -r requirements.txt`.
4. Убедитесь, что в `Templates` находится исходный `New Card Design.card`.
5. В приложении выберите сотрудника, нажмите «Подготовить фото» или «Создать пропуск (.card)».
6. Для печати откройте созданную копию `.card` в Magicard HUB 2.0.6 и выполните печать штатными средствами HUB.

## Важные ограничения интеграции

- Программа готовит отдельный файл `.card` с заменой содержимого изображения `images.jpg`; она не модифицирует оригинальный шаблон.
- Открытие/печать выполняется через штатный интерфейс Magicard HUB. Автоматическое подтверждение статуса физической печати не реализовано.
- У Magicard существует отдельный Magicard SDK для разработки приложений управления печатью и настройками принтера; производитель публикует точку получения SDK на techs.magicard.com/sdk. SDK — отдельный путь интеграции, а не доказательство наличия API у Magicard HUB. Для включения прямой печати нужно получить пакет SDK и руководство, проверить лицензионные условия и протестировать совместимость с установленным драйвером и Magicard 300. В текущей сборке SDK ещё не подключён.
- Общая база на несколько компьютеров, сетевые роли и полноценная аутентификация требуют отдельной серверной архитектуры. SQLite в текущей сборке предназначена для локальной базы.
- Срок действия хранится в карточке сотрудника, но автоматическое уведомление об истечении срока и аннулирование пропуска ещё не реализованы.
- Журнал фиксирует действия внутри приложения. Имя оператора берётся из системной переменной Windows `USERNAME` (или `USER`), поэтому это не криптографическая идентификация пользователя.

## Безопасная эксплуатация

- Ограничьте права Windows на папки `Employees`, `Backups`, `Config`, `Logs`, `Exports` только тем сотрудникам, которым они необходимы.
- Не размещайте папку приложения в общедоступной сетевой папке без ACL и резервирования.
- Не удаляйте `Backups`, пока не проверили восстановление на отдельной копии.
- Не отправляйте фотографии и базу сотрудников в публичные облака или мессенджеры.
- Для нескольких операторов используйте индивидуальные учётные записи Windows. Не используйте общую учётную запись.
- Защищайте резервные копии средствами шифрования диска Windows (например, BitLocker, если доступен).
- Проверяйте фактический результат печати на принтере; созданный файл не равен напечатанному пропуску.
