# Настройка обновлений PSразмер PRO через Яндекс Диск

## Как это работает

Программа уже настроена на публичную папку разработчика: https://disk.yandex.ru/d/3-8I5L5VUQpoEA. При необходимости ссылку можно изменить в окне обновления. Программа использует публичную ссылку на папку Яндекс Диска. При проверке она получает `manifest.json` через публичный REST API Яндекс Диска, читает номер версии, описание и имя ZIP. При скачивании получает временную ссылку на ZIP через тот же API, скачивает архив и сверяет SHA-256.

OAuth-токен Яндекса и установленное приложение Яндекс Диск на компьютере пользователя не нужны. Достаточно публичной ссылки на папку. Не размещайте в этой папке базу сотрудников, фотографии, резервные копии или другие личные данные.

## 1. Создайте папку для релизов

Например, `PSrazmer_PRO_Updates`. Внутри должны лежать только два файла последнего выпуска:

```text
PSrazmer_PRO_Updates/
  manifest.json
  PSrazmer_PRO_2.8.2_update.zip
```

Важно: `manifest.json` и ZIP должны находиться в одной папке. Имя ZIP в манифесте должно точно совпадать с именем загруженного файла.

## 2. Подготовьте выпуск

На Windows-компьютере разработчика:

1. Внесите изменения в проект и увеличьте `APP_VERSION` в `app/updater.py`.
2. Обновите версию приложения/установщика в `PSrazmer_PRO.iss`, если используете Inno Setup.
3. Запустите `build_windows.bat`.
4. Создайте пакет обновления:

```bat
python make_update_package.py 2.8.2 --notes "Исправлены ошибки;Улучшена работа с карточками"
```

В каталоге `update_release` появятся ZIP и `manifest.json`. Скрипт сам рассчитывает SHA-256 архива.

## 3. Опубликуйте файлы на Яндекс Диске

1. Откройте Яндекс Диск в браузере.
2. Откройте папку `PSrazmer_PRO_Updates`.
3. Загрузите в неё оба файла из `update_release`: ZIP и `manifest.json`.
4. Убедитесь, что загружены файлы именно последнего выпуска.
5. Включите доступ по ссылке для папки и скопируйте публичную ссылку на папку.
6. Проверьте ссылку в приватном окне браузера: содержимое папки должно быть доступно без входа в аккаунт.

Не используйте ссылку на отдельный ZIP. В программу вставляется ссылка на саму публичную папку.

## 4. Настройте клиентскую программу

На каждом компьютере:

1. Откройте PSразмер PRO.
2. Выберите `Программа → Проверить обновления…`.
3. Проверьте, что в поле уже указана папка разработчика. В обычной ситуации ничего вводить не нужно.
4. Нажмите `Проверить обновления`.
5. Если найдена более новая версия, проверьте список изменений и нажмите `Скачать и установить`.

Ссылка разработчика уже встроена как значение по умолчанию и также сохраняется в настройках программы. При следующих выпусках достаточно заменить ZIP и `manifest.json` в папке Яндекс Диска. Пользователям не нужно менять ссылку.

## 5. Как выпускать следующую версию

Каждый раз:

1. Увеличьте номер версии.
2. Соберите приложение.
3. Запустите `make_update_package.py` с новым номером версии.
4. Загрузите новый ZIP и новый `manifest.json` в ту же публичную папку, заменив старые файлы.
5. Пользователи нажимают «Проверить обновления».

Публикуйте сначала на отдельной тестовой папке и проверяйте обновление на тестовом компьютере. После успешной проверки переносите релиз в основную папку.

## Формат manifest.json

```json
{
  "version": "2.8.2",
  "package": "PSrazmer_PRO_2.8.2_update.zip",
  "sha256": "64 шестнадцатеричных символа SHA-256",
  "notes": [
    "Исправлены ошибки",
    "Улучшена работа с карточками"
  ]
}
```

## Важные ограничения и безопасность

- Публичная папка доступна всем, у кого есть ссылка. Не храните там конфиденциальные данные.
- SHA-256 проверяет целостность скачанного ZIP относительно манифеста. Это не криптографическая подпись разработчика: если злоумышленник сможет заменить и ZIP, и манифест в общей папке, одной SHA-256 недостаточно. Для коммерческого распространения следующий уровень защиты — цифровая подпись манифеста приватным ключом разработчика и проверка подписи в клиенте.
- Скачивание и установка автоматизированы только в собранной Windows-версии приложения. Для исходного Python-запуска доступна проверка, но не установка.
- Перед массовой установкой проверьте обновление на копии базы и на отдельном Windows 10/11 x64 компьютере.
- Пакет обновления не должен содержать `Config`, `Employees`, `History`, `Exports`, `Backups`, `Logs`, `Templates` и другие пользовательские каталоги. Существующий механизм исключает эти папки.
- Обновление накладывает файлы новой версии поверх старых и не удаляет файлы, отсутствующие в новом пакете. Удаление/миграцию файлов нужно выпускать отдельной проверенной процедурой.
